│

│   ├── news.py           # 新闻相关数据库操作
│   ├── users.py          # 用户相关数据库操作 ⭐新增
│   ├── favorites.py      # 收藏相关数据库操作 ⭐新增
│   └── histories.py      # 浏览历史数据库操作 ⭐新增

│   └── histories.py      # 浏览历史接口 ⭐新增
│

│   ├── __init__.py        # Python包标识

│

## 各层职责说明

### 1. Config（配置层）
- 数据库连接配置
- 连接池管理
- 会话工厂创建

### 2. Models（模型层）
- 定义数据库表结构
- ORM映射关系
- 字段类型和约束

### 3. CRUD（数据访问层）
- 封装所有数据库操作
- 提供统一的增删改查接口
- 处理SQL查询逻辑

### 4. Routers（路由层）
- 定义API端点
- 请求参数验证
- 调用CRUD层获取数据
- 返回统一格式的响应

### 5. Schemas（验证层）
- 请求数据验证
- 响应数据序列化
- 数据类型检查

### 6. Utils（工具层）
- JWT Token生成和验证
- 密码加密和解密
- 通用工具函数

## 数据流向

```
客户端请求 
    ↓
Routers（接收请求、验证参数）
    ↓
CRUD（执行数据库操作）
    ↓
Models（ORM映射）
    ↓
Database（MySQL）
    ↓
CRUD（返回结果）
    ↓
Routers（格式化响应）
    ↓
客户端收到响应
```

## 认证流程

```
1. 用户登录/注册
   ↓
2. 服务器验证凭据
   ↓
3. 生成JWT Token
   ↓
4. 返回Token给客户端
   ↓
5. 客户端在后续请求中携带Token
   ↓
6. 服务器验证Token有效性
   ↓
7. 提取用户ID并执行业务逻辑
```

## 运行环境要求

- Python 3.8+
- MySQL 5.7+ 或 8.0+
- 必要的Python包（见requirements.txt）

## 开发建议

1. **遵循分层架构**：不要在Router中直接写SQL
2. **使用异步操作**：所有数据库操作都是异步的
3. **统一响应格式**：{code, message, data}
4. **错误处理**：使用HTTPException抛出异常
5. **依赖注入**：使用FastAPI的Depends机制
6. **类型提示**：充分利用Python类型注解

## 常见问题

### Q: IDE显示导入错误怎么办？
A: 这是IDE的静态检查问题，确保：
1. 每个目录都有__init__.py
2. Python解释器选择正确
3. 已安装所有依赖包
4. 实际运行时不会有问题

### Q: 如何添加新功能？
A: 遵循以下步骤：
1. 在models/中定义数据模型
2. 在crud/中实现数据库操作
3. 在schemas/中定义验证模型
4. 在routers/中创建API接口
5. 在main.py中注册路由

### Q: 如何调试？
A: 使用以下方法：
1. 访问 http://127.0.0.1:8000/docs 查看Swagger文档
2. 运行 python test_api.py 进行自动化测试
3. 在db_config.py中设置echo=True查看SQL语句
4. 使用print()或logging记录日志
